## 特性

| 特性 | 说明 |
| --- | --- |
| **零依赖** | 只用 Node.js（≥ 20）内置模块，**不需要 npm install** |
| **三级 token 续期** | 缓存 → TGC 授权链 → 账密登录，**自动降级，无需人工干预** |
| **服务端为准** | 签到窗口、地理围栏、迟到线**全部从服务端下发**，脚本不写死 |
| **守望模式（常驻）** | 未成功每 5 分钟自动重试；**成功后休眠至次日继续守望**，不依赖重启电脑；到点仍未成功则**弹窗提醒** |
| **独立看门狗** | 计划任务每日自检，发现守望进程假死会自动清理并重新拉起，**与开机自启互为备份** |
| **开机自启** | 一键开关（写注册表 `HKCU\...\Run`），**完全隐藏窗口**运行 |
| **地理围栏** | 内置 WGS-84 → GCJ-02 转换 + 本地多边形判断 |

## 快速开始

### 1. 准备配置

复制模板并填写：

```bash
cp config.example.json config.json
```

或用**交互式管理面板**（推荐，双击即可）：

```
晚点名管理.bat
```

```
[1] 添加/修改 账号和签到地点     ← 首次使用选这个
[2] 显示已添加账号和签到地点
[3] 开机自动运行 开/关
[4] 立即测试一次签到
[5] 退出
```

### 2. 运行

```bash
node index.js --status    # 查询当前状态（验证链路是否通）
node index.js             # 一次性：等到开窗后签到，完成即退出
node index.js --watch     # 守望模式：失败自动重试（开机自启用的就是它）
```

## 三种运行模式

| 模式 | 命令 | 行为 |
| --- | --- | --- |
| **查询** | `node index.js --status` | 只显示当前考勤状态，**不提交** |
| **一次性** | `node index.js`（加 `--now` 跳过等待） | 完成一次签到流程后退出 |
| **守望** | `node index.js --watch` | **常驻进程**：未成功每 5 分钟重试；成功后休眠至次日 `wakeAt` 继续守望；到 `warnAt`（默认 21:55）仍未成功 → **弹窗提醒** |

守望模式带**单实例锁**（重复启动自动退出，锁含心跳，假死进程可被接管），日志写入 `logs/watch.log`。

> **⚠️ v1.1.0 架构修正（重要）**
>
> 旧版设计是「签到成功即退出」，而进程**只由开机/登录时的 Run 键拉起**。
> 若电脑连续多天不重启，签到成功后当天就再没有任何进程存在 —— 次日及以后**根本无人执行**，
> 连弹窗提醒也随进程一起消失，表现为「连续几晚静默漏签」。
>
> 现已改为**常驻守望**：成功后不退出，休眠至次日 `wakeAt`（默认 20:30）继续，
> 单个进程覆盖后续所有日期，**不再依赖每天重启电脑**。

## 配置字段

| 字段 | 说明 |
| --- | --- |
| `account` / `password` | 统一身份认证（教务）学号与密码 |
| `lng` / `lat` | **高德坐标（GCJ-02）**，填宿舍/教学楼附近（高德地图 App 长按取点） |
| `coordinateWGS84` | 若填的是 GPS 原始坐标，设为 `true` 自动转高德 |
| `restKey` | （可选）高德「Web 服务」Key，用于逆地理显示详细地址 |
| `wait` | 未开窗时是否挂机等待（默认 `true`） |
| `jitterSeconds` | 开窗后随机延迟 0~N 秒，模拟真人（默认 45） |
| `retryMinutes` | 守望模式重试间隔（默认 5 分钟） |
| `warnAt` | 预警时刻：到点仍未成功则弹窗提醒（默认 `21:55`） |
| `wakeAt` | **常驻守望苏醒时刻**：每天该时刻醒来准备签到（默认 `20:30`） |
| `retry` | 单轮提交失败重试次数 |
| `caIsNo` | 协议参数，保持 `"0"` |

## 运行机制

### token 三级自动续期

```
① .credential.json 里的业务 token  → 直接调 init 试探
② 失效 → 本地 SOURCEID_TGC 重走 authorize 授权链换新 token
③ 再失效 → 账密登 SSO（有控制台时可交互输短信码；
           隐藏运行时跳过，等下一轮重试）
```

### 签到流程

```
服务器时间窗校验
  → 本地多边形围栏判断
  → check.action 服务端校验
  → 高德逆地理生成地址
  → clockIn.action 提交
  → init 复核
```

### 守望模式（常驻）

```
每轮 runOnce
  → 失败睡 retryMinutes 再来
  → 成功 markSuccess + 休眠至次日 wakeAt（进程不退出，跨天持续守望）
  → 到 warnAt 仍失败 → 弹窗提醒 → 休眠至次日 wakeAt（不退出）
```

单实例锁为 `{pid, startedAt, heartbeat}`，进程每 30s 刷新心跳：

- 锁主心跳新鲜 → 新进程拒绝启动并**打印日志**（不再无声退出）
- 锁主心跳停滞超过 15 分钟（假死/僵尸）→ 新进程**接管**旧锁，旧进程在一个心跳周期内让位退出

### 独立看门狗

`scripts/watchdog.ps1` 由 Windows 计划任务 `LateNameWatchdog` 每天 21:30 / 22:30 / 23:30 调用，
**与 Run 键完全独立**，负责在守望进程失效时兜底：

```
① 查 .last-success 判断今日是否已签到
② 未签到且守望进程不存在/心跳停滞 → 清理假死进程并重新拉起
③ 已过 warnAt 仍未成功 → 弹窗提醒人工签到
```

> 判定守望进程存活**不能只看进程是否存在**：事故中的僵尸进程存活了 2 天多却早已停工，
> 只看进程数会误判为「有人在跑」而漏掉补救。因此以**锁文件心跳新鲜度**为准。

> 签到窗口 / 围栏 / 迟到线**全部以 `init.action` 服务端下发为准**，脚本不写死。

## 文件结构

```
晚点名管理.bat              管理面板（GBK + CRLF 编码，勿另存为 UTF-8）
manage.js                   交互式配置向导 / --show 只读展示
index.js                    主流程（--status / --now / --watch）

lib/
├── encrypt.js              AES-128-CBC（key = iv = "apexinfoapexinfo"）
├── sso.js                  统一身份认证登录（AES-ECB + 短信二验）
├── auth-chain.js           authorize → CAS → callback → index.action 取 token
├── api.js                  init / check / clockIn / currentTimestamp 封装
├── geo.js                  WGS-84 → GCJ-02 + 高德逆地理
├── notify.js               Windows 弹窗（msg.exe → PowerShell 降级）
├── util.js                 Cookie 罐 / HTTP / 多边形几何 / 时间
└── store.js                凭据本地缓存（.credential.json）

scripts/
├── autorun.vbs             开机自启隐藏入口
├── toggle-autostart.vbs    开关自启（写注册表 Run 键）
├── watchdog.ps1            独立看门狗（计划任务 LateNameWatchdog 调用）
└── schedule.ps1            （备用）PowerShell 轮询型定时

logs/
├── watch.log               守望模式日志
└── watchdog.log            看门狗日志
```

> **注意**：`scripts/*.ps1` 必须保存为 **UTF-8 with BOM**。PowerShell 5.1 会把无 BOM
> 的含中文脚本按 GBK 解析，导致语法错误、脚本无法执行。修改后请用编辑器确认编码。

## 常见问题

**Q：提示需要短信验证码？**

当前网络非校园网。建议在**校内网**运行；或临时用命令行跑一次完成登录（可交互输入验证码）。

**Q：弹窗没出现？**

弹窗优先用 `msg.exe`；部分系统（含开发机实测）**没有 `msg.exe`**，会自动降级为 PowerShell
`WScript.Shell.Popup`，该降级路径已实测可正常弹出。日志见 `logs/watch.log`。

**Q：签到成功后进程为什么还在？**

这是 v1.1.0 起的**刻意设计**（见上文架构修正）：常驻守望会休眠到次日 `wakeAt` 再签到。
**不要在任务管理器里手动结束它**，否则当天需等看门狗或下次开机才会重新拉起。

**Q：看门狗显示「未检测到守望进程」并重复拉起？**

正常情况下每天只应有一个守望进程。若反复出现，说明进程在频繁退出，请查看
`logs/watch.log` 与 `logs/watchdog.log` 定位原因。

**Q：提示「配置坐标不在签到围栏内」？**

坐标填错，或用了 WGS-84 原始值。请用高德地图取点，或设 `coordinateWGS84: true`。

**Q：学校改版导致失效？**

接口路径与加密参数见 `lib/*.js` 顶部注释，失效时按注释核对即可。

## 更新记录

### v1.1.0

**修复：连续多晚静默漏签（核心问题）**

- **守望模式改为常驻跨天**：旧版「签到成功即退出」+ 进程仅由开机/登录拉起，
  导致电脑多天不重启时后续每晚**无人执行且无任何提醒**。现改为成功后休眠至次日
  `wakeAt` 继续守望，单进程覆盖后续所有日期。
- **修复僵尸进程**：Windows 隐藏窗口下 `process.stdin.isTTY` 实测仍为 `true`，
  旧版 `makeSmsInput()` 忽略 `interactive` 参数只看 `isTTY`，导致每轮守望都创建
  `readline` 却从不关闭 —— stdin 句柄挂住事件循环，`main()` 返回后进程无法退出，
  日志已打印「进程退出」但进程实际存活数天。现统一走 `shutdown()`（先释放 stdin 再退出），
  且 `makeSmsInput(interactive)` 显式区分交互/非交互，返回的提问函数带 `close()`，
  调用方用 `finally` 保证关闭。
- **修复单实例锁死**：新增心跳（30s）与心跳过期接管，假死进程不再永久锁死；
  接管、拒绝**均写入日志**，杜绝无声失败。并修正两处锁判定缺陷：
  健康进程被误判「PID 复用」而抢锁；被接管后旧进程心跳把锁抢回造成双实例。
- **修复 `.ps1` 编码导致的脚本无法执行**：`scripts/*.ps1` 缺 UTF-8 BOM，
  PowerShell 5.1 按 GBK 解析含中文脚本报语法错误（`schedule.ps1` 3 处），已补齐。
- `.gitignore` 增补 `.watch.lock`（运行时锁文件，不应入库）。

**新增**

- `scripts/watchdog.ps1` 独立看门狗 + 计划任务 `LateNameWatchdog`
  （每天 21:30 / 22:30 / 23:30）：自检签到状态、抢救假死守望进程、超时弹窗提醒。
  判定存活以**锁文件心跳**为准（不能只看进程是否存在），并在强杀前二次复核，
  避免瞬时读锁失败误杀健康进程。
- 配置项 `wakeAt`（默认 `20:30`）：常驻守望每日苏醒时刻。
